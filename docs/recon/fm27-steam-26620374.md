# FM27 Steam build 26620374 (27.1.0)

An update on Steam on 17 November 2026 (app 4530370). On macOS `fm.app` reads version 27.1.0.2505117, and Steam fetched
about 2.0 GB for it (macOS depot 4530373, manifest 2172924661514683589, from 6658848859094881705).

Status: profiles for Windows, Apple silicon and Intel are in `profiles/fm27/steam-26620374*.toml`. Unlike build
26577676, the code grew on every platform and every function and static moved, so no earlier profile carries over.
The object layouts hold but for one byte (see "The finance record").

## Matching the functions and statics

- Functions: the bytes of each function of build 26577676 with the pc-relative operands masked (call and jump
  targets, `adrp`/`add`/`ldr` pairs on arm64, RIP-relative displacements on x86-64), searched for in the new binary.
  A unique match is the twin. Where a function matched more than once, its callers were matched and the call
  followed; where it changed, unique chunks inside it were matched and the nearest prologue before them taken.
- Statics and constants: the code around each reference in the old binary matched the same way, and the operand
  read from the new code. On arm64 `starting_loan.defaults` is loaded with `ldr q`, so its page offset is scaled
  by 16.
- Unit tests in `profile.rs` hold the result to build 26577676's: the same calls and arguments on Windows, and on
  macOS the tables 0x34178 (arm64) and 0x50180 (Intel) on, the managers 0x34010 and 0x50010.

Least certain, all on Intel: `start_loan` and `maximise_tactics` (both shrank; found by inner chunks), and
`officials`, `staff` and `save_system` (by their distance within the block; `officials` and `save_system` each have
one code site that agrees). They are the first to check in the game.

In the game under Rosetta all held but `maximise_tactics`: the first pick, `0x25967B0`, was the function after it
(the nearest prologue to a chunk that had moved past the function's new, shorter end) and Max tactics crashed FM. The
function is at `0x2595E20`: it opens as the old one does, walking its argument list for the tag `0x64726566` and
then asking the object's kind for `0x18`, and it is the fifth function of that shape in both binaries.

## The finance record

A club's finance record keeps its fields but the corporate facilities byte, which is at `0x8AA`, one after
`[club_finance] corporate = 0x8A9`. Read on Windows on Arsenal (20, with ticket price 50.75 still at `0x864`) and on
a second club with the full record (18). With the old offset the byte read 0, no record passed
`finances_look_real` and every club's finances showed as not kept. The profiles of this build set
`club_finance_corporate = 0x8AA`, which the session puts over the layout's value; earlier builds are unchanged.
