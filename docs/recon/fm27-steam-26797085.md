# FM27 Steam build 26797085 (27.1.1)

An update on Steam on 24 November 2026 (app 4530370). On macOS `fm.app` reads version 27.1.1.2511875, and Steam fetched
about 86 MB for it (macOS depot 4530373, manifest 2035111667504084235, from 2172924661514683589; Windows depot 4530372,
manifest 7950836655761563683).

Status: profiles for Windows, Apple silicon and Intel are in `profiles/fm27/steam-26797085*.toml`. A small update: the
code moved a little on every platform, so every function address changed, and the statics moved by a fixed distance on
macOS and barely at all on Windows. The object layouts hold, the corporate facilities byte of build 26620374 included
(`club_finance_corporate = 0x8AA`).

## Matching the functions and statics

The method is build 26620374's (docs/recon/fm27-steam-26620374.md): each function's bytes with the pc-relative
operands masked, searched for in the new binary, and each static read from the operand of the matched code around its
references.

- Functions: all but a few matched whole and once. `map_new` and `map_insert` (each one of many functions with the
  same body) were taken from the calls of matched callers, 36 and 39 callers agreeing on arm64, 36 and 40 on Windows,
  11 and 2 on Intel. On Windows `remove_work_permit` and `withdraw_offers` were found the same way (4 and 18 callers).
- Windows statics: all at build 26620374's addresses but three. `retirement_manager` is at `0x586F870` and
  `injury_manager` at `0x586F868`, each 0x20 on, and the `no_date` constant in the read-only data is at `0x4C58BBC`,
  0x10 on. The arrays are where they were: players `0x587B8B8`, staff `0x587B900`, clubs `0x587BA70`.
- arm64 statics: the tables and arrays are 0xFFF0 on (awards `0x57B2EB8`), the managers and the date 0x10000 on
  (date `0x5791DC8`, transfer manager `0x57849F8`, save system `0x5784BC0`).
- Intel statics: the tables and arrays are 0x6030 back (awards `0x5D4D238`, players `0x5D4D338`), the date and the
  injury and retirement managers 0x6020 back (date `0x5D2D6F0`). The transfer manager is at `0x5D21D40` and the save
  system at `0x5D210E0`, which is now before it.
- Unit tests in `profile.rs` hold the result to build 26620374's: the same calls and arguments on every platform, the
  statics above, and every other value unchanged.

Least certain before the game was run, all on Intel: `transfer_manager`, `save_system` and `map_insert`, and
`maximise_tactics` (`0x2596780`), whose first pick was wrong on build 26620374. All four held in the game under
Rosetta: the save's name read, the work permit, loan and transfer checks passed, and Max tactics ran with FM still
running.
