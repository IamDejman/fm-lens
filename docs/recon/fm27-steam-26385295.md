# FM27 Steam build 26385295 (27.0.1)

The first patch after release, on Steam on 10 November 2026 (app 4530370). FM's start screen reads 27.0.1. Sports
Interactive's notes list crash and stability fixes, translations and a fix for a freeze on Continue.

The patch rebuilt game_plugin on every platform. Nothing FM Lens reads changed shape: the object layouts
(`profiles/fm27/layout.toml`, `layout-macos.toml`) are those of 27.0.0, and every function FM Lens has the game run
takes what it took. Every static and every function sits at another address.

|---|---|---|
| macOS arm64 LC_UUID | `2A2D0ED6-324E-3D0D-A27D-10AEDBD0E270` | `F4540355-2186-39CB-9119-C706A6A35346` |
| macOS Intel LC_UUID | `94CDDC80-8474-327A-85E0-E4FF95DC6893` | `0981AB31-AC3B-3D93-944F-47FE4B59CD9E` |
| Windows size of image | `0x17CB9000` | `0x1821C000` |
| Windows link timestamp | `0x6AE8B5A4` | `0x6AE565AF` |

The Windows DLL's sections carry other names than in 27.0.0 (the code is `.data` here, `.xtext` there); the protection
renames them on each build. The code is the first section in both, at RVA `0x1000`.

## What moved

| | Statics in the data segment | The block of table pointers and arrays |
|---|---|---|
| macOS arm64 | +0x9C000 | +0x9C038 |
| macOS Intel | +0x7A000 | +0x7A020 |
| Windows | +0x11B040 | +0x11B040 |

Functions moved by amounts of their own, a few thousand bytes to about a megabyte, as code before them grew.

## How the profiles were made

No value was searched for again. Each was carried from the 27.0.0 profile of the same platform:

1. Split both builds' code into functions (`LC_FUNCTION_STARTS` on macOS, the exception directory on Windows).
2. Mask what an address change alters: branch and call targets, page and RIP-relative operands.
3. Pair the functions whose masked code is the same and occurs once in each build: 62,616 of 118,168 on arm64, 57,666
   of 119,550 on Intel, 42,893 of 139,131 on Windows, where the protection rewrites more of the code on each build.
4. Inside a paired function, each masked operand names the same thing in both builds, so it gives one old address and
   the new one. Every profile value took the address its references agreed on; none had two candidates.

The profiles are `steam-26385295-macos-arm64.toml`, `steam-26385295-macos-x86_64.toml` and `steam-26385295.toml`. The
notes on each value are 27.0.0's, with their addresses moved.

## The functions FM Lens calls

On both macOS halves all 26 are the same code as in 27.0.0 once addresses are masked. On arm64 `add_injury` swaps the
two targets of one conditional branch, which changes nothing it does.

On Windows 19 of the 26 are the same code. The other seven (`add_injury`, `remove_work_permit`, `withdraw_offers`,
`start_loan`, `date_value`, `map_insert`, `maximise_tactics`) are protected: their bytes in the file are not their
code in either build, so they cannot be compared there. Their entries were placed by their callers. The game's editor
calls `withdraw_offers` at `0x2A97CBC`, `leave_team` at `0x2A97CF2` and `cancel_offer` at `0x2A952BD`, each 0xC9400
after the same call in 27.0.0, and each lands on the mapped entry.
