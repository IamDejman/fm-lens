## 2. The call bridge (new, unproven in the game)

Some edits are objects and records only the game builds: injuries, work permits, loans, transfers with history and
finances, free-agent signings. FM Lens now has the game run its own functions for those.

- Protocol: `crates/fmlibre-mem/src/call.rs` (`Program`, `Step`, `Arg`, `Status`) and the `CALL` message in
  `crates/fmlibre-mem/src/macos/bridge.rs`. A program is up to 12 steps; each passes x0-x7, x8 and four stack slots,
  as values, addresses in a 1 KiB scratch block the editor pre-fills, or earlier steps' results. `STOP_IF_FALSE` and
  `CLEANUP` flags give a stop and clean-up path.
- Bridge: `crates/fmlibre-bridge/src/calls.rs`. Checks the sender's user, finds `game_plugin` in its own image list,
  checks its `LC_UUID`, refuses any RVA not in the build profile's `[calls]` table (generated by
  `crates/fmlibre-bridge/build.rs`), then runs the program on the main dispatch queue. Not started within 10 s:
  cancelled, never runs. arm64 only (inline asm trampoline).
- Editor: `Process::call` (macOS, writable, not `read-only`), `Session::call_game` in
  `crates/fmlibre-core/src/game_calls.rs`.
- Profile: `[calls]` in `profiles/fm27/steam-26340721-macos-arm64.toml` (`add_injury`, `set_work_permit`), plus
  `injury_kinds` and `injury_manager` statics and `[injury_kind]` in `layout-macos.toml`. `CallRvas` in profile.rs
  must list every key (`deny_unknown_fields`); the bridge reads the same table.
- An old bridge drops a CALL; the editor gets the kernel's send-once notice and says to set the bridge up again.
  **The installed bridge must be replaced before any call works**: quit Steam, install the new dylib (probe
  `bridge` command or the app's bridge setup), relaunch FM from Steam.

Built on top of it (core and Tauri only, no UI yet):

- `Session::injury_kinds()` (live: 136 kinds, probe `injury-kinds`), `Session::add_injury(player, kind_uid)`:
  `0x27047D4(INJURY_MANAGER, P, kind index, 3, 0, 0, 0, 0, [0, 0, 0])`. Only for a player with no injury, as FM's
  training does. Undo empties the list (as Heal does). Tauri: `injury_kinds`, `add_injury`, `Undo::Injured`.
- `Session::set_work_permit(player, grant)`: `0x2D85294(TRANSFER_MANAGER, P + vbase (0x388), [P+0x128], 1, grant)`.
  Verified by reading the permits back. Tauri: `set_work_permit`, `Undo::Permit`.
- `ConnectionInfo.gameActions { addInjury, workPermit }` says which of these this build supports.

## 3. What is left, in order

1. **UI for the two call actions**: done on `feat/call-actions-ui` (Add injury in Medical, Grant / Revoke in Work
   permit, both gated by `gameActions`, logged and undone from Changes). Preview checked; game check in section 4.
2. **Loan start**: done on `feat/loan-start` (Loan to a club in the Transfer dialog, gated by
   `gameActions.startLoan`). `Session::start_loan` fills the 0x70-byte STARTING_LOAN as the game's editor does at
   0x238D860 (`[starting_loan]` in the build profile and in `layout-macos.toml`) and calls
   `0x2E0A324(TRANSFER_MANAGER, &O, 1)`. Settled by disassembly: +0x18 is the player's identity block (P + vbase,
   0x388), not the object, since `0x2E0A324` reads the UID at `[O+0x18]+0xC` and calls the identity vtable's slot
   0x6E0. Undo sets `loan.ends` to today's game date; no recall function is known, so FM should end the loan on its
   next day. Both unproven in the game (section 4).
3. **Free-agent signing**: `0x2DFEDAC(TM, identity block, destination team, &terms map, &out[24], 0)` with an empty
   map built by `0x43F6B78` and destroyed after (see the call-shapes doc for the map and Value helpers).
   Medium-low confidence: test on one free agent only.
