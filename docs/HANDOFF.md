## 2. The call bridge (new, unproven in the game)

Some edits are objects and records only the game builds: injuries, work permits, loans, transfers with history and
finances, free-agent signings. FM Lens now has the game run its own functions for those.

- Protocol: `crates/fmlibre-mem/src/call.rs` (`Program`, `Step`, `Arg`, `Status`) and the `CALL` message in
  `crates/fmlibre-mem/src/macos/bridge.rs`. A program is up to 12 steps; each passes x0-x7, x8 and four stack slots,
  as values, addresses in a 1 KiB scratch block the editor pre-fills, or earlier steps' results. `STOP_IF_FALSE` and
  `CLEANUP` flags give a stop and clean-up path.
- Bridge: `crates/fmlibre-bridge/src/calls.rs`. Checks the sender's user, finds `game_plugin` in its own image list,
  checks its `LC_UUID`, refuses any RVA not in the build profile's `[calls]` table (generated by
  `crates/fmlibre-bridge/build.rs`), then runs the program on the main dispatch queue. Not started within 10 s:
  cancelled, never runs. arm64 only (inline asm trampoline).
- Editor: `Process::call` (macOS, writable, not `read-only`), `Session::call_game` in
  `crates/fmlibre-core/src/game_calls.rs`.
- Profile: `[calls]` in `profiles/fm27/steam-26340721-macos-arm64.toml` (`add_injury`, `set_work_permit`), plus
  `injury_kinds` and `injury_manager` statics and `[injury_kind]` in `layout-macos.toml`. `CallRvas` in profile.rs
  must list every key (`deny_unknown_fields`); the bridge reads the same table.
- An old bridge drops a CALL; the editor gets the kernel's send-once notice and says to set the bridge up again.
  **The installed bridge must be replaced before any call works**: quit Steam, install the new dylib (probe
  `bridge` command or the app's bridge setup), relaunch FM from Steam.

Built on top of it (core and Tauri only, no UI yet):

- `Session::injury_kinds()` (live: 136 kinds, probe `injury-kinds`), `Session::add_injury(player, kind_uid)`:
  `0x27047D4(INJURY_MANAGER, P, kind index, 3, 0, 0, 0, 0, [0, 0, 0])`. Only for a player with no injury, as FM's
  training does. Undo empties the list (as Heal does). Tauri: `injury_kinds`, `add_injury`, `Undo::Injured`.
- `Session::set_work_permit(player, grant)`: `0x2D85294(TRANSFER_MANAGER, P + vbase (0x388), [P+0x128], 1, grant)`.
  Verified by reading the permits back. Tauri: `set_work_permit`, `Undo::Permit`.
- `ConnectionInfo.gameActions { addInjury, workPermit, startLoan, signFreeAgent, endLoan, futureTransfer }` says which
  of these this build supports.

## 3. What is left, in order

1. **UI for the two call actions**: done on `feat/call-actions-ui` (Add injury in Medical, Grant / Revoke in Work
   permit, both gated by `gameActions`, logged and undone from Changes). Preview checked; game check in section 4.
2. **Loan start**: done on `feat/loan-start` (Loan to a club in the Transfer dialog, gated by
   `gameActions.startLoan`). `Session::start_loan` fills the 0x70-byte STARTING_LOAN as the game's editor does at
   0x238D860 (`[starting_loan]` in the build profile and in `layout-macos.toml`) and calls
   `0x2E0A324(TRANSFER_MANAGER, &O, 1)`. Settled by disassembly: +0x18 is the player's identity block (P + vbase,
   0x388), not the object, since `0x2E0A324` reads the UID at `[O+0x18]+0xC` and calls the identity vtable's slot
   0x6E0. Undo sets `loan.ends` to today's game date; no recall function is known, so FM should end the loan on its
   next day. Both unproven in the game (section 4).
3. **Free-agent signing**: done on `feat/free-agent-signing` (Sign on a free agent's profile, gated by
   `gameActions.signFreeAgent`; the Transfer dialog in a sign mode: club, optional wage and contract end).
   `Session::sign_free_agent` calls `0x2DFEDAC(TRANSFER_MANAGER, P + 0x278, senior team, &map, &refs, 0)` in one
   bridge program: `map_new` (`0x43F6B78`) builds the empty terms map in scratch, and the cleanup steps `refs_drop`
   (`0x43FE910`, takes `&vec`) and `map_drop` (`0x43F6C38`) run even if the signing stops. Settled by disassembly:
   x1 is the person block (P + 0x278), not the identity block, and the editor's IGE helpers can be skipped. Success
   is the true return plus his team now pointing at that club; FM's own contract is then overwritten with any wage or
   end given. Undo is a release (`plan_release`), so it refuses a human-managed club. Also fixed here: `log_loan`
   now updates the players list, so a loaned player shows his new club without a reload. Unproven in the game
   (section 4); test on one free agent only.
4. **Loan recall, releases, future transfers**: researched (fm27-call-shapes.md sections 4 and 5).
   - **End loan**: done on `feat/end-loan` (End loan on a loaned player's profile, gated by `gameActions.endLoan`,
     in the Release dialog). One game function ends any contract: `0x2D4B9DC(TM, P, contract, kind, 0, 1, 0, 0, stack
     0, 0)` (`end_contract` in the build profile); the daily loan expiry calls it on the loan contract (the P+0x2F8
     slot FM Lens already reads), so `Session::end_loan` does the same, with kind 2 for a parent club a human runs
     and 3 otherwise, and reads back that the loan is gone and he plays for his own club. Undo starts the loan again
     until its old end. Undoing a started loan now ends it at once too. Unproven in the game (section 4).
   - **Release through the game**: not a single call, so Release stays on FM Lens' own memory writes (they work and
     undo exactly). After emptying the slot, 0x2D4B9DC puts him in a team of the club of his main contract: for a
     loan that is the parent club, for his own contract his own club, so he would stay there with no contract. The
     editor follows it with 0x2d4f79c and the mover 0x2d49334 (kind 9) in a branch not yet settled (fm27-call-shapes.md
     section 4).
   - **Future transfers**: done on `feat/future-transfer-cancel` (a Joins date in the Sign dialog, gated by
     `gameActions.futureTransfer`). A day after today adds the 'TrDt' term to the signing's map (`date_type`,
     `date_value`, `map_insert`, `value_drop` in the build profile), so FM agrees the signing now and makes it on that
     day, on its own terms (no wage or end). `Session::sign_free_agent_later` reads back one new dated record and his
     pending offer (`[future_transfer]` in `layout-macos.toml`). Undo cancels it as the game's editor does:
     `cancel_offer` (0x2D180B4) on the offer with a reference held (`ref_copy`, `ref_drop`), then
     `drop_dated_transfer` (0x1827808). Unproven in the game (section 4).
5. **Officials editing**: done on `feat/official-edits` (Edit on an official's profile: current and potential
   ability, reputation, birth date, one official at a time). `Entity::Official` in `edit.rs`, offsets from
   `[official]`, checked by the UID at +0x134; a new `officials` health check (every list entry of the first's class,
   with a UID, a birth date and values in range) guards the writes. The list's open profile now follows each read,
   so edited values show at once. Referee attributes stay read-only until their labels are known. Unproven in the
   game (section 4).
